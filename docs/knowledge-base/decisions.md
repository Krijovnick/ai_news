## 2026-11-10 — Fetch не вызывается для Reddit; «нет подходящих результатов» поиска — INFO

По `logs/app.log` Fetch API DeepSeek (`POST /v1/tools/fetch`) падал только на URL Reddit (все 3 сбоя — 404), на других доменах ошибок не было. Текст поста при этом уже есть из PRAW (`description`/`text`), поэтому для хостов `reddit.com`, его поддоменов (`www.`, `old.`, `np.` и т.п.) и `redd.it` fetch не вызывается: материал идёт в статью с текстом из источника, URL остаётся в ссылках статьи и в дедупликации поиска. Хост проверяется по распарсенному URL (`notreddit.com`, `reddit.com.evil.org` — обычные домены, fetch вызывается). Пропуск — DEBUG, без WARNING. Список хостов — константа `FETCH_SKIP_HOSTS` в `utils/deepseek.py`, не env.

«Search DeepSeek: нет подходящих результатов» понижено с WARNING до INFO: поиск ответил, просто всё отсеялось по `rerank_score >= 1.5` или дублям. Настоящие ошибки Search/Fetch (сеть, HTTP, пустой или битый ответ) остаются WARNING.

Подробности: [program.md](program.md) — «DeepSeek», пункт «Сбор текстов».

## 2026-11-10 — Уточнения повторов DeepSeek, открытия базы и кодов /api/manual-run

- `SSLError` и `ProxyError` у `chat/completions` не повторяются, хотя наследуют `ConnectionError`: это ошибки настройки сертификатов или прокси, за 20 с паузы они не исправятся, а повторы только задержат падение.
- `Retry-After` у 429 принимается и в формате HTTP-date: пауза = разница с текущим временем UTC, тот же потолок 60 с и правило «не меньше своей паузы»; некорректная или прошедшая дата — своя пауза.
- Уборка старых `failed` при открытии базы (`NewsDatabase.__init__`) — по возможности: ошибка (например, `database is locked`) пишется WARNING, база открывается.
- `/api/manual-run`: HTTP 400 только для невалидного ввода (пустое тело, не список, нет полной пары, после фильтров не осталось материалов) — отдельное исключение `ManualInputError`, не `ValueError`. Любая ошибка самого прогона, в том числе `ValueError` из разбора ответа DeepSeek и ошибка `validate_config`, — `{ok:false, error}` и HTTP 500. Ошибка `validate_config` раньше давала 400.

Подробности: [program.md](program.md) — «DeepSeek» («Повторы chat/completions»), «База SQLite», «Веб».

## 2026-11-10 — Повтор запросов chat/completions при временных сбоях

В прогоне 2026-11-10 одна из 5 статей не написалась: соединение с DeepSeek оборвалось посреди ответа (`ChunkedEncodingError: Response ended prematurely`), а запрос делался один раз. Теперь повтор сделан на уровне общего вызова `chat/completions`, поэтому покрывает и разбор недели, и план, и статьи: до 2 повторов с паузами 5 и 15 с при обрыве ответа, ошибке соединения, таймауте, HTTP 429 (с учётом `Retry-After`, не больше 60 с) и 5xx. Прочие 4xx (в том числе 402 Payment Required, 400, 401) и неразобранный ответ модели не повторяются: повтор их не исправит. Каждый повтор — WARNING. После исчерпания попыток поведение прежнее: ошибка плана и разбора пробрасывается, статья пропускается с ERROR. Настройки — константы в коде, не env. Search/Fetch API не трогали. Повтор после обрыва посреди ответа может повторно тратить токены (DeepSeek мог уже сгенерировать часть ответа) — принято осознанно: потерянная статья дороже. Худший случай одного вызова — около 3×300 с плюс паузы; ручной разбор в вебе ждёт соответственно дольше, у фронтенда своего таймаута нет.

Подробности: [program.md](program.md) — раздел «DeepSeek», «Повторы chat/completions» и пункт «Написание».

## 2026-11-10 — Упавшие прогоны не хранятся и не видны в вебе

Прогон с критической ошибкой (полный `main.py` и «Свои тексты» / `POST /api/manual-run`) больше не остаётся в базе со статусом `failed`: строка `runs` удаляется вместе с `items`, `summaries`, `articles` и `proposed`-ключами этого прогона; у `active`/`rejected` с этим `run_id` обнуляется `run_id`. Ошибка — только в `logs/app.log`, в Telegram по-прежнему ничего. Ответ `/api/manual-run` при ошибке прежний по смыслу: `{ok:false, error}` и HTTP 500. Старые `failed`-строки удаляются тем же каскадом при каждом открытии базы (`NewsDatabase.__init__`): при старте `main.py`, при старте веба и на каждом запросе веба — одно место для обоих процессов. Если каскадное удаление упавшего прогона само упало, оно откатывается, а прогон помечается `failed` (запасной вариант: не застревает в `running`, скрыт в вебе и доудаляется при следующем открытии базы). Ошибка уведомления в Telegram или отметки `telegram_sent` после `finish_run('ok')` только логируется: успешный прогон остаётся `ok`. Пустые прогоны (`delete_runs_without_items`) удаляются тем же каскадом. Веб дополнительно не отдаёт `failed` в списке и по `/api/runs/<id>` (404). `running` не трогается.

Заменяет прежнее правило «критическая ошибка: статус `failed`, текст в `error_text`».

Подробности: [program.md](program.md) — разделы «Режимы запуска», «База SQLite», «Веб».

## 2026-11-02 — Статьи: план по заголовкам с ранжированием, топ-5, Search/Fetch DeepSeek, факты только из источников

План тем строится только по заголовкам материалов (номер, источник, заголовок; без текстов) плюс разбор недели и заголовки последних 40 статей. Модель снимает смысловые дубли, объединяет материалы по прежнему строгому правилу, ранжирует темы и отдаёт топ-`ARTICLES_PER_RUN` (по умолчанию снова 5) с 0–2 поисковыми запросами на тему. Тексты для статьи собирает программа: текст из источника, полный текст по URL через Fetch API DeepSeek, дополнительные источники через Search API DeepSeek (`rerank_score >= 1.5`, до `ARTICLE_SEARCH_RESULTS` на запрос); ошибки fetch/search — WARNING без падения прогона; отключается `DEEPSEEK_WEB_TOOLS`. ## 2026-11-02 — Статьи: план тем + отдельный запрос на статью, без лимита

Статьи генерируются в два шага: план (группировка материалов по темам, с учётом заголовков последних 40 статей) и отдельный запрос на каждую статью только с её материалами. ## 2026-09-29 — Web.bat: один Ctrl+C без Y/N

`Web.bat` через `start` открывает рабочее окно с одной командой `cmd /d /c` (cd в каталог скрипта, адрес, «Остановка: Ctrl+C», `python web.py`; при ненулевом коде — `pause`) и сразу `exit`, закрывая запускалку. Сайт крутится не как bat-задание, поэтому Ctrl+C не спрашивает «Terminate batch job (Y/N)?». `web.py` ловит KeyboardInterrupt, печатает «Веб-интерфейс остановлен.» и выходит с кодом 0 — окно закрывается само. `Collect.bat` не менялся.

Подробности: [program.md](program.md) — раздел «Режимы запуска».

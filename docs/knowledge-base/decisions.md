# Журнал решений

Свежие записи сверху. Каждая запись: дата, что решили, где это отражено в базе.

## 2026-10-26 — Промпты DeepSeek только из YAML, без fallback в коде

Запасные полные тексты промптов в `utils/deepseek.py` убраны: единственный источник — `PROMPTS_PATH` (`prompts/deepseek.yaml`). При отсутствии файла, ошибке YAML или невалидной структуре — явное исключение и лог; прогон с «тихими» дефолтами не продолжается. В коде допускается только список обязательных ключей/секций без формулировок инструкций.

Подробности: [program.md](program.md) — раздел «DeepSeek».

## 2026-10-26 — Единый файл промптов DeepSeek

Все промпты DeepSeek (разбор недели, статьи+keywords, голос автора, system-роли) вынесены в `prompts/deepseek.yaml` (`PROMPTS_PATH`). Правка текстов без смены логики клиента. Отдельный `prompts/author.txt` больше не используется.

**Superseded** по пункту «запасные тексты при отсутствии файла»: см. запись выше «Промпты DeepSeek только из YAML, без fallback в коде».

Подробности: [program.md](program.md) — раздел «DeepSeek».

## 2026-10-12 — Ссылки у статей и в «Свои тексты»

У сгенерированных статей хранится `source_urls` (JSON-массив URL из материалов прогона). DeepSeek указывает их в ответе; в БД попадают только URL из `items`. В «Свои тексты» у каждой пары опциональное поле «Ссылка» уходит в `POST /api/manual-run` как `url` (или `link`) материала; пустой URL по-прежнему допустим.

Подробности: [program.md](program.md) — разделы «База SQLite», «DeepSeek», «Веб».

## 2026-10-05 — Свои тексты в вебе

Меню «Свои тексты» отправляет введённые пары заголовок+текст в тот же разбор, что новости: без опроса источников и без порога релевантности 20, с языком заголовка по буквам, дублями и похожими заголовками. В Telegram по-прежнему одно уведомление со ссылкой на сайт. Пустой URL не считается общим адресом при снятии дублей.

Подробности: [program.md](program.md) — раздел «Веб».

Подробности: [program.md](program.md) — раздел «Веб».

## 2026-10-05 — X и LinkedIn: дата поста, тело текста, поиск LinkedIn

Посты X и LinkedIn берутся только если дату публикации удалось прочитать и она не старше `NEWS_LOOKBACK_DAYS` (текущее время вместо даты не подставляется). Заголовок и текст — тело поста после разворота Show more / see more, не вся карточка. Поиск X: active-ключевые слова, оператор `since:YYYY-MM-DD` и `f=live`. LinkedIn: страницы компаний и поиск по active-ключевым словам (`LINKEDIN_MAX_QUERIES`, `past-week`, сортировка по дате). После дублей список идёт от новых к старым.

Подробности: [program.md](program.md) — разделы Twitter/X и LinkedIn (источник позже удалён, см. запись 2026-10-05 «LinkedIn и Twitter/X удалены из сбора»).

## 2026-09-29 — Пустой прогон не пишется в SQLite

Прогон без материалов после фильтров больше не создаёт строку в `runs` и не шлёт Telegram («разбор готов» было бы ложью). Сбор и фильтры идут как раньше; DeepSeek и запись в базу — только при ≥1 материале. Критическая ошибка после создания прогона по-прежнему `failed` без Telegram. Существующие прогоны без `items` удалены одноразово из `data/news.db`.

## 2026-09-29 — Web.bat: один Ctrl+C без Y/N

`Web.bat` через `start` открывает рабочее окно с одной командой `cmd /d /c` (cd в каталог скрипта, адрес, «Остановка: Ctrl+C», `python web.py`; при ненулевом коде — `pause`) и сразу `exit`, закрывая запускалку. Сайт крутится не как bat-задание, поэтому Ctrl+C не спрашивает «Terminate batch job (Y/N)?». `web.py` ловит KeyboardInterrupt, печатает «Веб-интерфейс остановлен.» и выходит с кодом 0 — окно закрывается само. `Collect.bat` не менялся.

Подробности: [program.md](program.md) — раздел «Режимы запуска».

## 2026-09-29 — Отклик кнопок и попап «Сохранить» на ключевых словах

На `/keywords` все кнопки (Добавить, Сохранить, Удалить, Поправить, Принять, Отклонить) показывают наведение и нажатие; пока идёт fetch-запрос, нажатая кнопка остаётся «вдавленной» и не принимает второй клик. После успешного `action=edit` (JSON `ok=true`) показывается короткое сообщение на русском с текстом фразы (через `textContent`); при ошибке попапа нет. Для остальных действий — только отклик нажатия. Стили нажатия общие в `base.html`.

Подробности: [program.md](program.md) — раздел «Веб».

## 2026-09-29 — Ключевые слова без перезагрузки страницы

На `/keywords` добавление, правка (active и proposed), удаление, принятие и отклонение идут fetch-POST с заголовком `X-Requested-With: fetch`. Успех — JSON `{"ok": true, ...}` (для add/edit/accept/reject ещё `id` и `phrase`) и HTTP 200 без redirect; ошибка — JSON `{"ok": false, "error": "..."}` и HTTP 400. Со страницы меняется только затронутая фраза (строка / список rejected), прокрутка и остальной UI не сбрасываются. Обычный POST без заголовка по-прежнему редиректит.

Подробности: [program.md](program.md) — раздел «Веб».

## 2026-09-29 — Удаление ключевого слова без перезагрузки страницы

На `/keywords` удаление active-фразы через кнопку «Удалить» идёт fetch-POST с заголовком `X-Requested-With: fetch`; сервер отвечает JSON `{"ok": true}` без redirect. Со страницы убирается только строка этой фразы, прокрутка и остальной UI не сбрасываются. Обычный POST без заголовка по-прежнему редиректит.

Подробности: [program.md](program.md) — раздел «Веб».

## 2026-09-29 — HN: стоп при недоступности сети; LinkedIn: вход по cookie li_at

Hacker News при `ConnectionError`/`Timeout`/`OSError` к Firebase или Algolia пишет одну строку в лог и прекращает соответствующий шаг (без запроса каждой истории и оставшихся ключевых слов); пауза ~0.3 с между запросами Algolia; проверка сертификатов не отключается. LinkedIn считает вход выполненным при наличии cookie `li_at` в сессии браузера (значение никуда не пишется); страница по-прежнему не перезагружается, пока входа нет.

Подробности: [program.md](program.md) — разделы «Google News и Hacker News», LinkedIn (источник позже удалён, см. запись 2026-10-05 «LinkedIn и Twitter/X удалены из сбора»).

## 2026-09-29 — LinkedIn: без перезагрузки во время входа

Цикл ожидания входа больше не вызывает `page.reload()` / повторный `goto`: из‑за обновлений каждые 3 с сбрасывался вход через Google. Страница открывается один раз; до обнаружения входа вкладка не уводится. Вход подтверждают только URL и локаторы навигации/формы, не HTML целиком и не один адрес `/feed/`.

Подробности: [program.md](program.md) — раздел LinkedIn (источник позже удалён, см. запись 2026-10-05 «LinkedIn и Twitter/X удалены из сбора»).

## 2026-09-29 — HTTPS сбора через системные сертификаты Windows

`requests` по умолчанию доверяет только пакету certifi и падает на self-signed в цепочке (антивирус/прокси), хотя браузер и хранилище Windows такому сертификату доверяют. В начале сбора вызывается `truststore.inject_into_ssl()`; `verify=False` запрещён.

Подробности: [program.md](program.md) — раздел «HTTPS и сертификаты».

# Что должна делать программа

Один ручной прогон собирает материалы про ИИ за последние `NEWS_LOOKBACK_DAYS` дней (по умолчанию 7). DeepSeek пишет подробный разбор недели и несколько авторских статей на русском. Всё сохраняется в SQLite. Отдельный веб-процесс показывает разборы и статьи, принимает свои тексты на разбор и позволяет править ключевые слова. В Telegram уходит одно короткое уведомление после успешного прогона.

Академические статьи и голые анонсы моделей в разбор не нужны. Язык материалов — английский или русский.

YouTube-парсер и старый суммаризатор удалены из репозитория. Разбор делает `utils/deepseek.py`.

## Режимы запуска

Запуск из корня проекта, с настроенным `.env`.

| Команда | Файл Windows | Что делает |
|---------|--------------|------------|
| `python main.py` | `Collect.bat` | Полный недельный прогон: сбор, фильтр, DeepSeek, SQLite, одно сообщение в Telegram |
| `python main.py --test` | — | Проверка источников: по одному запросу к каждому включённому парсеру. Без Telegram и без записи разбора в базу. Лог в консоль и `logs/app.log` |
| `python web.py` | `Web.bat` | Веб на `http://127.0.0.1:5050`. Сбор источников не запускает; свои тексты запускают разбор |
| `python test_aggregator.py` | — | Локальные проверки без сети, браузера и боевого Telegram |
| `python install.py` | — | Установка зависимостей и каталогов (`logs`, `data`) |

Рабочий запуск только этими командами. Неизвестный аргумент CLI (`python main.py …`) пишется в лог и завершает процесс с кодом 2, без сбора.

`Collect.bat` в конце ждёт нажатия клавиши. `Web.bat` открывает рабочее окно отдельной командой `cmd /c` (сайт крутится не как bat-задание), поэтому Ctrl+C не спрашивает «Terminate batch job (Y/N)?»; окно-запускалка сразу закрывается. `pause` только если `python web.py` завершился с ненулевым кодом.

Ошибка одного источника не останавливает остальные. Критическая ошибка прогона в Telegram **не** отправляется: статус `failed`, текст в `error_text` и в `logs/app.log`.

## База SQLite

Файл: `data/news.db`. Каталог `data/` (включая `news.db`) в `.gitignore`. Режим WAL, чтобы веб мог читать во время записи.

Таблицы:

| Таблица | Поля |
|--------|------|
| `runs` | `id`, `started_at`, `finished_at`, `status` (`running` / `ok` / `failed`), `lookback_days`, `error_text` (протокол ошибок источников; может быть пустым при `ok`), `telegram_sent` |
| `items` | `id`, `run_id`, `source`, `title`, `url`, `text`, `published_at`, `score`, `extra_json` |
| `summaries` | `id`, `run_id`, `body` — один разбор на прогон |
| `articles` | `id`, `run_id`, `title`, `body`, `rationale`, `source_urls` (TEXT: JSON-массив URL материалов, на которых основана статья; пустой массив/`null` — ссылок нет) |
| `keywords` | `id`, `phrase`, `status` (`active` / `proposed` / `rejected`), `run_id` (nullable), `updated_at` |

Уникальность фразы без учёта регистра.

В поиск идут **только** `status=active`. `proposed` не используются, пока пользователь не примет их в вебе. `rejected` повторно не предлагать.

### Стартовый набор ключевых слов

При первом запуске (и при открытии веба), если активных слов нет, засеять компактный набор (~15–25 фраз):

- `AI automation`, `AI agents`, `AI for business`, `AI use case`, `AI workflow`, `online business AI`, `AI didn't work`, `AI case study`, `AI implementation`, `AI success story`, `AI failed`, `AI coding agents`, `AI tools for developers`
- `ИИ`, `ИИ-автоматизация`, `агенты`, `онлайн-бизнес с ИИ`, `кейсы внедрения`, `что получилось и что не получилось`, `ИИ автоматизация`, `ИИ для бизнеса`, `кейс внедрения ИИ`, `онлайн бизнес с ИИ`

Старый гигантский список `AI_KEYWORDS` больше не источник поисковых фраз. `EXCLUDE_KEYWORDS` и штраф за голые анонсы моделей (`ANNOUNCEMENT_PENALTY_KEYWORDS`) остаются.

## Источники

Флаги: `ENABLE_GOOGLE_NEWS`, `ENABLE_HACKERNEWS`, `ENABLE_REDDIT` (по умолчанию `true`). Выключенный источник пишется в протокол прогона, а не молча пропадает.

Общий список active-ключевых слов из базы — для всех источников.

Лимиты сбора: Google News до 60, Hacker News до 50, Reddit AI-часть до 50, Reddit бизнес-часть до 50.

### Reddit

AI-сабы (`REDDIT_SUBREDDITS`): практические сабы про ИИ (ChatGPT, ClaudeAI, OpenAI, Automate, n8n, LocalLLaMA, Artificial, singularity, AI_Agents и похожие). Без общих бизнес-сабов Entrepreneur / startups / SaaS / indiehackers — они в бизнес-списке.

Бизнес-сабы только онлайн (`REDDIT_BUSINESS_SUBREDDITS`): `indiehackers`, `SaaS`, `SideProject`, `microsaas`, `Entrepreneur`, `startups`, `sidehustle`, `juststart`. Офлайн-ориентированные (`sweatystartup`, `smallbusiness` и похожие) не входят.

Пост из бизнес-саба проходит только если он про ИИ (совпадение с active-ключевыми словами или явный ИИ-смысл: AI, ИИ, нейросет) **и** это онлайн-бизнес, а не офлайн. Офлайн, вакансии, курсы быстрых денег отсекаются `REDDIT_BUSINESS_EXCLUDE_KEYWORDS` и явными offline-словами. Отдельный режим Reddit Business и отдельная отправка в Telegram удалены; сбор бизнес-постов входит в общий прогон (`search_business_posts` и связанные настройки `REDDIT_BUSINESS_*`).

### Google News и Hacker News

Поиск по active-ключевым словам из базы, не по зашитым `DISCOVERY_KEYWORDS` / `AI_KEYWORDS`.

**Hacker News:** один `requests.Session` на прогон парсера. Сначала top/best через Firebase (`hacker-news.firebaseio.com`), затем поиск Algolia по active-словам (`hn.algolia.com`) с паузой ~0.3 с между запросами. При ошибке соединения (`ConnectionError` / `Timeout` / `OSError`) к спискам Firebase — одна запись в лог, шаг Firebase прекращается, истории по id не запрашиваются. Если список id уже получен, но конкретная история падает с ошибкой соединения — цикл историй останавливается сразу, одна запись в лог (не ERROR на каждый id). Обычные HTTP-ответы (404, пустая история) эту историю пропускают, источник не останавливают. При первой ошибке соединения к Algolia — оставшиеся ключевые слова не запрашиваются, одна запись в лог. Успешные истории фильтруются как раньше (ключевые слова, свежесть, score). Проверку сертификатов не отключать.

## Фильтрация после сбора

Порядок обязателен:

1. Удалить дубликаты (одинаковый заголовок без регистра или одинаковый URL). Пустой URL не считается адресом и сам по себе дубли не создаёт.
2. Оставить английский или русский заголовок.
3. Релевантность не ниже 20 (практика выше; `ANNOUNCEMENT_PENALTY_KEYWORDS` снижают балл; `EXCLUDE_KEYWORDS` отсекаются на источниках).
4. Итоговый рейтинг: релевантность × 0.7 + популярность × 0.3.
5. Сортировка по рейтингу, при равенстве — по дате (свежее выше).
6. Убрать похожие заголовки (как раньше: общий кусок с края).

`DIGEST_MAX_ITEMS` больше **не** обрезает то, что уходит в модель или Telegram. В модель и в `items` идут все материалы после фильтра. Если материалов много для одного запроса — резать на части, затем собрать в один разбор. В промпт текст каждого материала обрезать примерно до 800 символов, плюс заголовок, источник, url.

## DeepSeek

Переменные окружения (только имена): `DEEPSEEK_API_KEY`, `DEEPSEEK_MODEL` (по умолчанию `deepseek-chat`), `ARTICLES_PER_RUN` (по умолчанию 5), `PROMPTS_PATH` (по умолчанию `prompts/deepseek.yaml`). Без ключа полный прогон не стартует (`validate_config`). Также нужны `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`; Reddit credentials — если `ENABLE_REDDIT`.

API: `https://api.deepseek.com/v1/chat/completions`.

Все system/user-промпты DeepSeek (разбор недели целиком, по частям и склейка; статьи и keywords; голос автора; system-роли) лежат в одном файле `PROMPTS_PATH` — это единственный источник текстов; запасных копий в коде нет. Тексты с динамикой — шаблоны с плейсхолдерами (`{materials}`, `{summary}`, `{n}`, `{idx}`, `{total}`, `{partials}`, `{author}` и т.п.). Правка формулировок без смены кода клиента. Если файл отсутствует, YAML битый или структура неполная (нет обязательных секций/ключей) — ошибка с понятным сообщением и запись в лог; разбор DeepSeek не выполняется.

В базу пишется:

1. **Разбор недели** — подробный русский текст: о чём пишут, какие технологии появились, чем помогают, где применять.
2. **Статьи** — не пересказ каждой новости. Модель выбирает до `ARTICLES_PER_RUN` самых полезных тем и пишет по каждой отдельный текст. Если полезного меньше — меньше; ноль статей допустим, если материалов нет. Голос: женщина с большим опытом в ИИ и разработке, от первого лица, как устная речь перед аудиторией, подробно и плавно. Предложения на русском, без английских вставок вроде «это game changer». Названия продуктов и компаний остаются в оригинальном написании (Claude, Hugging Face, n8n). У каждой статьи модель указывает `source_urls` — URL из входных материалов прогона, на которых основан текст; сохраняются только URL из `items` этого прогона (выдуманные отбрасываются). Если опиралась на материал без URL — список пустой.
3. **Новые ключевые слова** — технологии и формулировки из материалов, которых нет среди active и rejected. Сохранять как `proposed`, привязать к `run_id`. В следующий поиск не попадают, пока их не примут.

Пустой сбор (ничего после фильтров): строку в `runs` не создавать; в `items` / `summaries` / `articles` ничего не писать; DeepSeek и Telegram не вызывать. Протокол источников и факт пустого прогона — только в `logs/app.log`. Строка прогона появляется только когда после фильтров есть хотя бы один материал.

## HTTPS и сертификаты

HTTPS-запросы сбора (Hacker News, DeepSeek и остальные через `requests`) используют хранилище сертификатов Windows через пакет `truststore` (`truststore.inject_into_ssl()` в начале `main.py`), чтобы доверять сертификатам антивируса и локального прокси. Отключение проверки сертификатов (`verify=False` и аналоги) **запрещено**.

## Telegram


После успешного прогона ровно одно сообщение: разбор готов, смотреть на `http://127.0.0.1:5050`. Без перечня новостей, без сводки источников, без пачки ошибок. Пометить `telegram_sent`.

Ошибки прогона в Telegram не слать.

Логи: `logs/app.log`, уровень `LOG_LEVEL` (по умолчанию INFO).

## Веб

Отдельный процесс Flask. Хост `127.0.0.1`, порт `5050`. Flask отдаёт JSON и собранный Vue 3 (Vite) из `frontend/dist`. Шаблонов Jinja нет. Сбор источников не запускает. При открытии сайта создаются схема и стартовые слова, если их ещё нет.

В шапке меню «Свои тексты». По клику открывается панель, не отдельный маршрут. В панели пары «заголовок + текст + ссылка»: сначала одна, кнопка «Ещё» добавляет ещё, «Убрать» есть у пары, если их больше одной. Лимита на число пар нет. У каждой пары поле «Ссылка» (URL) опционально: пустое не блокирует «Ок». «Ок» неактивна, пока нет хотя бы одной пары, где и заголовок, и текст непустые после срезания пробелов. Пустые пары на сервер не отправляются. Пока запрос идёт, «Ок» с классом `is-busy` и не принимает второй клик, в панели видно «Идёт разбор…». Успех закрывает панель и открывает `/run/<id>`. Ошибка остаётся текстом в панели (не через HTML).

`POST /api/manual-run` принимает JSON `{ "items": [ {"title", "text", "url"?} ] }` (вместо `url` допустимо `link`). Пустое тело, не список или ни одной полной пары — `{ok:false, error}` и HTTP 400, прогон не создаётся. Каждая полная пара — материал как новость: `title`, `description` = текст пользователя, `source` = «Вручную», `url` = переданная ссылка или пустая строка, `published_date` = сейчас UTC. Дальше тот же разбор, что у новостей после сбора: DeepSeek (разбор, статьи до `ARTICLES_PER_RUN`, proposed-ключи), запись items/summary/articles, `finish_run` ok, одно уведомление в Telegram. Источники не опрашиваются.

К своим текстам не применяется порог релевантности 20. Язык заголовка — русский или английский по буквам (кириллица или латиница среди букв, не меньше 3, одна из долей больше 0.8); кавычки, тире и прочая пунктуация заголовок не отбрасывают. Проверка языка собранных новостей не ослабляется. Дубли и похожие заголовки снимаются теми же методами, что у обычного прогона. Если после этого материалов нет — строку в `runs` не создавать, DeepSeek и Telegram не вызывать, JSON с ошибкой на русском и HTTP 400. Без ключа DeepSeek и без настроек Telegram прогон не стартует (`validate_config`). Ошибку прогона в Telegram не слать. Если прогон уже создан и разбор упал — статус `failed`, в панели текст ошибки.

Адрес, страницы и правила ключевых слов те же. Обычный POST `/keywords` без заголовка `X-Requested-With: fetch` при успехе по-прежнему редиректит на `/keywords`. Запрос с этим заголовком отвечает JSON без redirect.

Страницы:

- **Главная** — недели от новых к старым (календарная ISO-неделя по `started_at`). Внутри недели прогоны по дате; у каждого ссылка на разбор.
- **Страница прогона** — статус, протокол ошибок если есть, текст разбора, список статей (API отдаёт у статей и `source_urls`).
- **Страница статьи** — заголовок и текст целиком; блок «Использованные ссылки» со списком кликабельных URL из `source_urls`, если список непустой (пустой блок не показывают).
- **Ключевые слова** — active: править, удалить, добавить; proposed: принять (→ active), поправить фразу, убрать (→ rejected); rejected — свёрнутым списком. Добавление, правка, удаление, принятие и отклонение меняют только затронутую фразу, страница не перезагружается. Кнопки (Добавить, Сохранить, Удалить, Поправить, Принять, Отклонить) визуально показывают наведение и нажатие; пока идёт запрос к серверу, нажатая кнопка остаётся «вдавленной» и не принимает второй клик; после ответа состояние снимается. После успешного «Сохранить» (`action=edit`, JSON `ok=true`) появляется короткое сообщение на русском с текстом сохранённой фразы; оно само исчезает через несколько секунд и его можно закрыть. При ошибке сохранения (ошибка, дубликат, пустая фраза) попапа успеха нет, остаётся текст ошибки. Для «Поправить», «Добавить», «Удалить», «Принять», «Отклонить» попап сохранения не нужен — только отклик нажатия.

Пустая база: главная говорит, что прогонов ещё нет; ключевые слова всё равно редактируются.

## Чего программа не делает

- YouTube не подключён (парсер удалён).
- Старый суммаризатор удалён; разбор только через DeepSeek.
- LinkedIn и Twitter/X не подключены (парсеры удалены).
- Отключение проверки TLS-сертификатов запрещено (см. раздел «HTTPS и сертификаты»).

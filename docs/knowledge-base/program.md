# Что должна делать программа

Один ручной прогон собирает материалы про ИИ за последние `NEWS_LOOKBACK_DAYS` дней (по умолчанию 7). DeepSeek пишет подробный разбор недели и несколько авторских статей на русском. Всё сохраняется в SQLite. Отдельный веб-процесс показывает разборы и статьи, принимает свои тексты на разбор и позволяет править ключевые слова. В Telegram уходит одно короткое уведомление после успешного прогона.

Академические статьи и голые анонсы моделей в разбор не нужны. Язык материалов — английский или русский.

YouTube-парсер и старый суммаризатор удалены из репозитория. Разбор делает `utils/deepseek.py`.

## Режимы запуска

Запуск из корня проекта, с настроенным `.env`.

| Команда | Файл Windows | Что делает |
|---------|--------------|------------|
| `python main.py` | `Collect.bat` | Полный недельный прогон: сбор, фильтр, DeepSeek, SQLite, одно сообщение в Telegram |
| `python main.py --test` | — | Проверка источников: по одному запросу к каждому включённому парсеру. Без Telegram и без записи разбора в базу. Лог в консоль и `logs/app.log` |
| `python web.py` | `Web.bat` | Веб на `http://127.0.0.1:5050`. Сбор источников не запускает; свои тексты запускают разбор |
| `python test_aggregator.py` | — | Локальные проверки без сети, браузера и боевого Telegram |
| `python install.py` | — | Установка зависимостей и каталогов (`logs`, `data`) |

Рабочий запуск только этими командами. Неизвестный аргумент CLI (`python main.py …`) пишется в лог и завершает процесс с кодом 2, без сбора.

`Collect.bat` в конце ждёт нажатия клавиши. `Web.bat` открывает рабочее окно отдельной командой `cmd /c` (сайт крутится не как bat-задание), поэтому Ctrl+C не спрашивает «Terminate batch job (Y/N)?»; окно-запускалка сразу закрывается. `pause` только если `python web.py` завершился с ненулевым кодом.

Ошибка одного источника не останавливает остальные. Критическая ошибка прогона в Telegram **не** отправляется. Текст ошибки пишется в `logs/app.log`. Упавший прогон в базе не остаётся: строка `runs` и всё, что к ней привязано, удаляется (`items`, `summaries`, `articles`, `proposed`-ключи этого прогона; у `active`/`rejected` с этим `run_id` только обнуляется `run_id`). Удаление идёт одной транзакцией; если оно само упало — откат, прогон помечается `failed` (в вебе не виден, доудаляется при следующем открытии базы), исходная ошибка прогона пробрасывается. Ошибка отправки уведомления или отметки `telegram_sent` после того, как прогон помечен `ok`, только пишется в лог: прогон остаётся `ok`. Прогоны со статусом `running` (идущие) не трогаются.

## База SQLite

Файл: `data/news.db`. Каталог `data/` (включая `news.db`) в `.gitignore`. Режим WAL, чтобы веб мог читать во время записи.

Таблицы:

| Таблица | Поля |
|--------|------|
| `runs` | `id`, `started_at`, `finished_at`, `status` (`running` / `ok`; `failed` только временно, если каскадное удаление не удалось), `lookback_days`, `error_text` (протокол ошибок источников; может быть пустым при `ok`), `telegram_sent` |
| `items` | `id`, `run_id`, `source`, `title`, `url`, `text`, `published_at`, `score`, `extra_json` |
| `summaries` | `id`, `run_id`, `body` — один разбор на прогон |
| `articles` | `id`, `run_id`, `title`, `body`, `rationale`, `source_urls` (TEXT: JSON-массив URL, на которых основана статья: материалы темы из `items` и дополнительные источники из поиска DeepSeek, переданные в запрос статьи; пустой массив/`null` — ссылок нет) |
| `keywords` | `id`, `phrase`, `status` (`active` / `proposed` / `rejected`), `run_id` (nullable), `updated_at` |

Уникальность фразы без учёта регистра.

Старые строки `runs` со `status=failed` (от прежних версий) удаляются тем же каскадом при каждом открытии базы (`NewsDatabase`: старт `main.py`, старт веба и запросы веба). `running` не трогается. Эта уборка — по возможности: если она упала (например, `database is locked`), в лог WARNING, база всё равно открывается, `failed` доудалятся при следующем открытии.

В поиск идут **только** `status=active`. `proposed` не используются, пока пользователь не примет их в вебе. `rejected` повторно не предлагать.

### Стартовый набор ключевых слов

При первом запуске (и при открытии веба), если активных слов нет, засеять компактный набор (~15–25 фраз):

- `AI automation`, `AI agents`, `AI for business`, `AI use case`, `AI workflow`, `online business AI`, `AI didn't work`, `AI case study`, `AI implementation`, `AI success story`, `AI failed`, `AI coding agents`, `AI tools for developers`
- `ИИ`, `ИИ-автоматизация`, `агенты`, `онлайн-бизнес с ИИ`, `кейсы внедрения`, `что получилось и что не получилось`, `ИИ автоматизация`, `ИИ для бизнеса`, `кейс внедрения ИИ`, `онлайн бизнес с ИИ`

Старый гигантский список `AI_KEYWORDS` больше не источник поисковых фраз. `EXCLUDE_KEYWORDS` и штраф за голые анонсы моделей (`ANNOUNCEMENT_PENALTY_KEYWORDS`) остаются.

## Источники

Флаги: `ENABLE_GOOGLE_NEWS`, `ENABLE_HACKERNEWS`, `ENABLE_REDDIT` (по умолчанию `true`). Выключенный источник пишется в протокол прогона, а не молча пропадает.

Общий список active-ключевых слов из базы — для всех источников.

Лимиты сбора: Google News до 60, Hacker News до 50, Reddit AI-часть до 50, Reddit бизнес-часть до 50.

### Reddit

AI-сабы (`REDDIT_SUBREDDITS`): практические сабы про ИИ (ChatGPT, ClaudeAI, OpenAI, Automate, n8n, LocalLLaMA, Artificial, singularity, AI_Agents и похожие). Без общих бизнес-сабов Entrepreneur / startups / SaaS / indiehackers — они в бизнес-списке.

Бизнес-сабы только онлайн (`REDDIT_BUSINESS_SUBREDDITS`): `indiehackers`, `SaaS`, `SideProject`, `microsaas`, `Entrepreneur`, `startups`, `sidehustle`, `juststart`. Офлайн-ориентированные (`sweatystartup`, `smallbusiness` и похожие) не входят.

Пост из бизнес-саба проходит только если он про ИИ (совпадение с active-ключевыми словами или явный ИИ-смысл: AI, ИИ, нейросет) **и** это онлайн-бизнес, а не офлайн. Офлайн, вакансии, курсы быстрых денег отсекаются `REDDIT_BUSINESS_EXCLUDE_KEYWORDS` и явными offline-словами. Отдельный режим Reddit Business и отдельная отправка в Telegram удалены; сбор бизнес-постов входит в общий прогон (`search_business_posts` и связанные настройки `REDDIT_BUSINESS_*`).

### Google News и Hacker News

Поиск по active-ключевым словам из базы, не по зашитым `DISCOVERY_KEYWORDS` / `AI_KEYWORDS`.

**Hacker News:** один `requests.Session` на прогон парсера. Сначала top/best через Firebase (`hacker-news.firebaseio.com`), затем поиск Algolia по active-словам (`hn.algolia.com`) с паузой ~0.3 с между запросами. При ошибке соединения (`ConnectionError` / `Timeout` / `OSError`) к спискам Firebase — одна запись в лог, шаг Firebase прекращается, истории по id не запрашиваются. Если список id уже получен, но конкретная история падает с ошибкой соединения — цикл историй останавливается сразу, одна запись в лог (не ERROR на каждый id). Обычные HTTP-ответы (404, пустая история) эту историю пропускают, источник не останавливают. При первой ошибке соединения к Algolia — оставшиеся ключевые слова не запрашиваются, одна запись в лог. Успешные истории фильтруются как раньше (ключевые слова, свежесть, score). Проверку сертификатов не отключать.

## Фильтрация после сбора

Порядок обязателен:

1. Удалить дубликаты (одинаковый заголовок без регистра или одинаковый URL). Пустой URL не считается адресом и сам по себе дубли не создаёт.
2. Оставить английский или русский заголовок.
3. Релевантность не ниже 20 (практика выше; `ANNOUNCEMENT_PENALTY_KEYWORDS` снижают балл; `EXCLUDE_KEYWORDS` отсекаются на источниках).
4. Итоговый рейтинг: релевантность × 0.7 + популярность × 0.3.
5. Сортировка по рейтингу, при равенстве — по дате (свежее выше).
6. Убрать похожие заголовки (как раньше: общий кусок с края).

`DIGEST_MAX_ITEMS` больше **не** обрезает то, что уходит в модель или Telegram. В модель и в `items` идут все материалы после фильтра. Если материалов много для одного запроса — резать на части, затем собрать в один разбор. В промпт текст каждого материала обрезать примерно до 800 символов, плюс заголовок, источник, url.

## DeepSeek

Переменные окружения (только имена): `DEEPSEEK_API_KEY`, `DEEPSEEK_MODEL` (по умолчанию `deepseek-chat`), `ARTICLES_PER_RUN` (по умолчанию 5 — потолок топа тем, которые план отдаёт на статьи; 0 — без потолка), `ARTICLE_ITEM_TEXT_CHARS` (по умолчанию 4000 — до скольких символов обрезается каждый текст в запросе на одну статью: текст из источника, полный текст страницы, текст результата поиска), `DEEPSEEK_WEB_TOOLS` (по умолчанию включено; `true`/`1` — вызывать Search/Fetch API DeepSeek при сборе текстов статей, `false`/`0` — не вызывать), `ARTICLE_SEARCH_RESULTS` (по умолчанию 3 — сколько результатов поиска брать на один поисковый запрос), `PROMPTS_PATH` (по умолчанию `prompts/deepseek.yaml`). Без ключа полный прогон не стартует (`validate_config`). Также нужны `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`; Reddit credentials — если `ENABLE_REDDIT`.

API: `https://api.deepseek.com/v1/chat/completions`. Для сбора текстов статей — Fetch API `POST https://api.deepseek.com/v1/tools/fetch` (тело `{"url"}`, ответ `{title, content}` в Markdown) и Search API `POST https://api.deepseek.com/v1/tools/search` (тело `{"query", "count", "need_content": true}`, ответ `results` с `rerank_score`, `title`, `url`, `content`, `summary` и др.); авторизация тем же `DEEPSEEK_API_KEY`, таймаут 60 с.

**Повторы chat/completions.** Каждый запрос к `chat/completions` (разбор недели целиком, по частям и склейка; план; статья) при временном сбое повторяется: обрыв ответа посреди передачи (`ChunkedEncodingError`, «Response ended prematurely»), ошибка соединения, таймаут (300 с на попытку), HTTP 429 и 5xx. `SSLError` и `ProxyError` (формально ошибки соединения) не повторяются: это ошибки настройки сертификатов или прокси, пауза их не исправит. До 2 повторов (всего 3 попытки) с паузами 5 и 15 с (константы `CHAT_RETRY_DELAYS` в `utils/deepseek.py`, не env); для 429 пауза — не меньше `Retry-After`, но не больше 60 с (`CHAT_RETRY_AFTER_MAX`). `Retry-After` принимается в секундах или в формате HTTP-date (тогда — разница с текущим временем UTC); некорректное значение или прошедшая дата — своя пауза. Остальные 4xx (400, 401, 402 Payment Required, 404 и т.д.) не повторяются. Неразобранный ответ модели (не JSON, нет полей), не-JSON тело ответа API и битая структура ответа API не повторяются. Каждый повтор — WARNING в лог: шаг (например, «план статей», «статья «…»»), номер попытки из общего числа, ошибка, пауза. После исчерпания попыток ошибка идёт дальше как раньше: план и разбор недели — пробрасывается (прогон падает), статья — пропускается с ERROR. Search/Fetch API не повторяются (у них свои правила, см. «Сбор текстов»). Худший случай одного вызова `chat/completions` — около 3×300 с плюс паузы (5 + 15 с, у 429 до 60 + 60 с), то есть примерно 15–17 минут; ручной разбор «Свои тексты» в вебе делает несколько таких вызовов подряд и в худшем случае ждёт ответа соответственно дольше (фронтенд своего таймаута на `/api/manual-run` не ставит).

Все system/user-промпты DeepSeek (разбор недели целиком, по частям и склейка; статьи и keywords; голос автора; system-роли) лежат в одном файле `PROMPTS_PATH` — это единственный источник текстов; запасных копий в коде нет. Тексты с динамикой — шаблоны с плейсхолдерами (`{materials}`, `{summary}`, `{idx}`, `{total}`, `{partials}`, `{author}`, `{recent_titles}`, `{limit}`, `{topic}`, `{angle}`, `{why_together}`, `{extra_sources}` и т.п.). Правка формулировок без смены кода клиента. Если файл отсутствует, YAML битый или структура неполная (нет обязательных секций/ключей) — ошибка с понятным сообщением и запись в лог; разбор DeepSeek не выполняется.

В базу пишется:

1. **Разбор недели** — подробный русский текст: о чём пишут, какие технологии появились, чем помогают, где применять.
2. **Статьи** — не пересказ каждой новости. Генерация в три шага:
   - **План — только по заголовкам.** Один запрос получает номер, источник и заголовок каждого материала (тексты материалов в план не идут), разбор недели (для ранжирования) и заголовки последних 40 статей из базы. Модель снимает смысловые дубли (похожие заголовки про одно событие — одна тема, не несколько), объединяет материалы по правилу ниже, отбрасывает проходное и **ранжирует** темы по значимости и интересу, возвращая не больше `ARTICLES_PER_RUN` самых сильных тем от главной к менее важной; меньше — если достойных меньше, ноль допустим, темы ради количества не придумываются. Темы прошлых статей не повторяются, кроме случаев существенно нового развития (тогда статья про это новое). По каждой теме: о чём статья, главная мысль, что общего у материалов, номера материалов и 0–2 поисковых запроса (`search_queries`, до 128 символов, на английском или русском) — если для статьи стоит найти дополнительные источники в интернете. Заодно — новые ключевые слова. Код обрезает темы до `ARTICLES_PER_RUN` в порядке модели и пишет в лог (INFO) выбранные темы с заголовками и URL их материалов. Ошибка запроса плана (после повторов, см. «Повторы chat/completions») прерывает разбор (пробрасывается).
   - **Объединение материалов** в одну тему — только если они про одну и ту же ситуацию, событие или проблему с общим механизмом или причиной (один релиз в разных источниках, один инцидент, одна уязвимость/сбой с общей причиной). Общая область («агенты ошиблись», «новые модели», «безопасность ИИ») — не повод объединять: разные ошибки — разные статьи. При сомнении — разделять. Один материал входит не более чем в одну тему.
   - **Сбор текстов (делает программа, не модель).** По каждой выбранной теме: текст каждого материала из источника (`description`/`text`); полный текст страницы по URL материала через Fetch API (материал без URL — без fetch); по каждому из `search_queries` — Search API, из ответа берутся результаты с `rerank_score >= 1.5`, не дублирующие URL материалов темы и уже взятых результатов, не больше `ARTICLE_SEARCH_RESULTS` на запрос; текст результата — `content`, если пуст — `summary`. Все тексты обрезаются до `ARTICLE_ITEM_TEXT_CHARS`. Любая ошибка fetch/search (сеть, HTTP 4xx/5xx включая 429, пустой ответ) — WARNING в лог, статья пишется по тому, что есть (минимум — текст из источника); прогон не падает. При выключенном `DEEPSEEK_WEB_TOOLS` Search/Fetch не вызываются. Проверка сертификатов не отключается (см. «HTTPS и сертификаты»).
   - **Написание.** По каждой теме отдельный запрос: по каждому материалу — заголовок, URL, текст из источника и полный текст (если скачан); отдельным блоком «Дополнительные источники из поиска» — заголовок, URL, текст. **Факты, цифры, названия, даты, цитаты — только из переданных материалов и дополнительных источников**: ничего не выдумывается и не добавляется из памяти модели; если фактов мало — статья короче, а не с домыслами. Анализ, выводы, последствия, практические рекомендации — нужны как авторская позиция, но без новых фактов. В статье: что произошло, почему (механизм — насколько видно из материалов), собственный анализ (последствия, неочевидные выводы, риски), практические выводы. Без банальностей, структура не по одному шаблону. Стилистические запреты: без пафосного акцента на символизме и важности («служит напоминанием», «играет ключевую роль», «поворотный момент», «неизгладимый след» и т.п.); без дидактических и редакционных оговорок («важно отметить», «стоит учесть», «значения могут варьироваться» и т.п.); без отдельного раздела или подраздела-резюме с пересказом написанного («Итоги», «Резюме», «В заключение»).
   Голос: женщина с большим опытом в ИИ и разработке, от первого лица, как устная речь перед аудиторией, подробно и плавно. Предложения на русском, без английских вставок вроде «это game changer». Названия продуктов и компаний остаются в оригинальном написании (Claude, Hugging Face, n8n). `source_urls` статьи — URL материалов её темы из `items` этого прогона (по номерам из плана) плюс URL дополнительных источников из поиска, которые реально были переданы в запрос статьи; без дублей и не из текста ответа модели. Материал без URL ссылку не даёт. Если одна статья не написалась (ошибка сети или HTTP после повторов, другая ошибка 4xx без повторов, неразбираемый ответ) — она пропускается с ERROR в лог, остальные сохраняются, прогон не падает. Если ответ DeepSeek обрезан по `max_tokens` (`finish_reason == "length"`) — предупреждение в лог.
3. **Новые ключевые слова** — технологии и формулировки из материалов, которых нет среди active и rejected. Сохранять как `proposed`, привязать к `run_id`. В следующий поиск не попадают, пока их не примут.

Пустой сбор (ничего после фильтров): строку в `runs` не создавать; в `items` / `summaries` / `articles` ничего не писать; DeepSeek и Telegram не вызывать. Протокол источников и факт пустого прогона — только в `logs/app.log`. Строка прогона появляется только когда после фильтров есть хотя бы один материал.

## HTTPS и сертификаты

HTTPS-запросы сбора (Hacker News, DeepSeek и остальные через `requests`) используют хранилище сертификатов Windows через пакет `truststore` (`truststore.inject_into_ssl()` в начале `main.py`), чтобы доверять сертификатам антивируса и локального прокси. Отключение проверки сертификатов (`verify=False` и аналоги) **запрещено**.

## Telegram


После успешного прогона ровно одно сообщение: разбор готов, смотреть на `http://127.0.0.1:5050`. Без перечня новостей, без сводки источников, без пачки ошибок. Пометить `telegram_sent`.

Ошибки прогона в Telegram не слать.

Логи: `logs/app.log`, уровень `LOG_LEVEL` (по умолчанию INFO).

## Веб

Отдельный процесс Flask. Хост `127.0.0.1`, порт `5050`. Flask отдаёт JSON и собранный Vue 3 (Vite) из `frontend/dist`. Шаблонов Jinja нет. Сбор источников не запускает. При открытии сайта создаются схема и стартовые слова, если их ещё нет.

В шапке меню «Свои тексты». По клику открывается панель, не отдельный маршрут. В панели пары «заголовок + текст + ссылка»: сначала одна, кнопка «Ещё» добавляет ещё, «Убрать» есть у пары, если их больше одной. Лимита на число пар нет. У каждой пары поле «Ссылка» (URL) опционально: пустое не блокирует «Ок». «Ок» неактивна, пока нет хотя бы одной пары, где и заголовок, и текст непустые после срезания пробелов. Пустые пары на сервер не отправляются. Пока запрос идёт, «Ок» с классом `is-busy` и не принимает второй клик, в панели видно «Идёт разбор…». Успех закрывает панель и открывает `/run/<id>`. Ошибка остаётся текстом в панели (не через HTML).

`POST /api/manual-run` принимает JSON `{ "items": [ {"title", "text", "url"?} ] }` (вместо `url` допустимо `link`). Пустое тело, не список или ни одной полной пары — `{ok:false, error}` и HTTP 400, прогон не создаётся. HTTP 400 — только для ошибок ввода (проверка до прогона и отдельное исключение `ManualInputError` в `main.py`); тип `ValueError` для этого не используется. Каждая полная пара — материал как новость: `title`, `description` = текст пользователя, `source` = «Вручную», `url` = переданная ссылка или пустая строка, `published_date` = сейчас UTC. Дальше тот же разбор, что у новостей после сбора: DeepSeek (разбор, статьи, proposed-ключи), запись items/summary/articles, `finish_run` ok, одно уведомление в Telegram. Источники не опрашиваются.

К своим текстам не применяется порог релевантности 20. Язык заголовка — русский или английский по буквам (кириллица или латиница среди букв, не меньше 3, одна из долей больше 0.8); кавычки, тире и прочая пунктуация заголовок не отбрасывают. Проверка языка собранных новостей не ослабляется. Дубли и похожие заголовки снимаются теми же методами, что у обычного прогона. Если после этого материалов нет — строку в `runs` не создавать, DeepSeek и Telegram не вызывать, JSON с ошибкой на русском и HTTP 400. Без ключа DeepSeek и без настроек Telegram прогон не стартует (`validate_config`): строка в `runs` не создаётся, ответ `{ok:false, error}` и HTTP 500 (ошибка настройки, а не ввода). Ошибку прогона в Telegram не слать. Если прогон уже создан и разбор упал (любая ошибка, в том числе `ValueError` из разбора ответа DeepSeek) — `{ok:false, error}` с текстом ошибки и HTTP 500, в панели текст ошибки; прогон и привязанные строки удаляются из базы (как у полного прогона), в списке прогонов его нет.

Адрес, страницы и правила ключевых слов те же. Обычный POST `/keywords` без заголовка `X-Requested-With: fetch` при успехе по-прежнему редиректит на `/keywords`. Запрос с этим заголовком отвечает JSON без redirect.

Страницы:

- **Главная** — недели от новых к старым (календарная ISO-неделя по `started_at`). Внутри недели прогоны по дате; у каждого ссылка на разбор. Прогоны со `status=failed` не показываются (`/api/weeks`); `/api/runs/<id>` и `POST /api/runs/<id>/articles` для такого прогона отвечают 404, как будто его нет.
- **Страница прогона** — статус, протокол ошибок если есть, текст разбора, список статей (API отдаёт у статей и `source_urls`).
- **Страница статьи** — заголовок и текст целиком; блок «Использованные ссылки» со списком кликабельных URL из `source_urls`, если список непустой (пустой блок не показывают).
- **Правка и удаление статьи** — на странице статьи кнопки «Редактировать» и «Удалить пост». «Редактировать» открывает форму: заголовок, текст (textarea), обоснование («Почему эта тема»), список ссылок — у каждой поле ввода и «Удалить», кнопка «Добавить ссылку»; число ссылок не ограничено. «Сохранить» / «Отмена». Пока запрос идёт, нажатая кнопка с классом `is-busy` и не принимает второй клик. После успешного сохранения показывается обновлённая статья и короткое сообщение «Статья сохранена» (само исчезает, можно закрыть); при ошибке форма остаётся открытой с текстом ошибки (не через HTML). «Удалить пост» спрашивает подтверждение (`confirm`), после удаления открывается страница прогона статьи; там список статей перезапрашивается, удалённой в нём нет. Удаления со страницы прогона нет.

`PUT /api/articles/<id>` (или `PATCH`) принимает JSON `{ "title", "body", "rationale"?, "source_urls": [...] }`. Заголовок и текст срезаются по пробелам; пустой — `{ok:false, error}` и HTTP 400. Ссылки: срезать пробелы, пустые убрать, дубли убрать (порядок первого вхождения), разрешены только `http://` и `https://` URL с хостом; иначе HTTP 400 с ошибкой «Некорректная ссылка: … Нужен адрес, начинающийся с http:// или https://», статья не меняется. Пустой список ссылок допустим (блок ссылок исчезает). Если `rationale` или `source_urls` не переданы — поле остаётся прежним. Тело не JSON-объект — HTTP 400. Успех — `{ok:true, article}`. `DELETE /api/articles/<id>` удаляет строку из `articles` — `{ok:true}`. Нет статьи — `{ok:false, error:"Статья не найдена"}` и HTTP 404. Ошибки на русском.
- **Свой пост в прогоне** — на странице прогона под списком статей кнопка «Добавить пост». Она открывает ту же форму, что и правка статьи (общий компонент `ArticleForm`): заголовок, текст, обоснование (необязательно), список ссылок без лимита с «Добавить ссылку»/«Удалить», «Сохранить» / «Отмена», нажатая кнопка `is-busy` пока идёт запрос. После успешного сохранения пост добавляется в конец списка статей прогона без перезагрузки и показывается короткое сообщение «Пост добавлен: …» (само исчезает, можно закрыть); при ошибке форма остаётся открытой с текстом ошибки (не через HTML). Свой пост хранится в `articles` как обычная статья прогона (схема не меняется, отдельного признака нет), дальше правится и удаляется как любая другая.

`POST /api/runs/<run_id>/articles` принимает JSON `{ "title", "body", "rationale"?, "source_urls"?: [...] }`. Проверки заголовка, текста и нормализация ссылок — те же, что у `PUT /api/articles/<id>`; не переданные `rationale` и `source_urls` — пустая строка и пустой список. Успех — `{ok:true, article}` и HTTP 201. Невалидные данные или тело не JSON-объект — `{ok:false, error}` и HTTP 400, статья не создаётся. Нет прогона — `{ok:false, error:"Прогон не найден"}` и HTTP 404. Создание поста не запускает DeepSeek и не шлёт Telegram.
- **Ключевые слова** — active: править, удалить, добавить; proposed: принять (→ active), поправить фразу, убрать (→ rejected); rejected — свёрнутым списком. Добавление, правка, удаление, принятие и отклонение меняют только затронутую фразу, страница не перезагружается. Кнопки (Добавить, Сохранить, Удалить, Поправить, Принять, Отклонить) визуально показывают наведение и нажатие; пока идёт запрос к серверу, нажатая кнопка остаётся «вдавленной» и не принимает второй клик; после ответа состояние снимается. После успешного «Сохранить» (`action=edit`, JSON `ok=true`) появляется короткое сообщение на русском с текстом сохранённой фразы; оно само исчезает через несколько секунд и его можно закрыть. При ошибке сохранения (ошибка, дубликат, пустая фраза) попапа успеха нет, остаётся текст ошибки. Для «Поправить», «Добавить», «Удалить», «Принять», «Отклонить» попап сохранения не нужен — только отклик нажатия.

Пустая база: главная говорит, что прогонов ещё нет; ключевые слова всё равно редактируются.

## Чего программа не делает

- YouTube не подключён (парсер удалён).
- Старый суммаризатор удалён; разбор только через DeepSeek.
- LinkedIn и Twitter/X не подключены (парсеры удалены).
- Отключение проверки TLS-сертификатов запрещено (см. раздел «HTTPS и сертификаты»).
